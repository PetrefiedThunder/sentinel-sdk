# Backend QA report

Scope: Python SDK HTTP client, configuration and `@oversight` decorator. This repository contains a client library, not a backend server. All requests were intercepted by `httpx.MockTransport`; the root QA fixture additionally blocks real sockets. No production service, credentials, tenant, SMS destination or database was used.

Backend counts: **Critical=0 High=1 Medium=5 Low=0**. Product code is unchanged. The new module has **72 passing cases and 16 strict expected failures** representing six findings. The property test additionally checks 75 deterministic recursive JSON examples. Findings remain unfixed; expected-failure markers keep these regressions visible without turning normal CI red.

## Findings

Run the exact reproduction selectors with `.venv/bin/python -m pytest tests/test_qa_backend.py --runxfail -q -k '<selector>'`. The normal run omits `--runxfail`. [Negative-control output](artifacts/BACKEND-negative-controls.txt) proves all 16 assertions fail without their expected-failure markers; [normal output](artifacts/BACKEND-focused-final.txt) records the green marked run.

## Passing checks and local auth matrix

| Scenario | Local evidence | Scope of conclusion |
| --- | --- | --- |
| No configured API key | Two sync/async cases raise `SentinelConfigError` before constructing a transport. | SDK rejects missing configuration. |
| Server rejects unauthorized or forbidden request | 401 and 403 are included in the 18 HTTP-status cases; status/detail are preserved and there is one POST only. | SDK propagates denial; actual server authorization is untested. |
| Distinct synthetic tenants/clients | Two concurrent clients send their own host and authorization header. | SDK clients do not overwrite each other's captured credentials. This does not prove server tenant isolation. |
| Same client, concurrent operations | Ten async requests retain their distinct idempotency keys and request data. | Header/body isolation is verified under cooperative async concurrency. |
| Rejected, unknown, absent or conflicting decision | Eight cases never invoke protected function; explicit rejection takes precedence over secondary approved decision. | Local decorator fails closed on these decision shapes. |
| Approval timeout | Default reject fallback does not execute. Explicit execute fallback does not apply to 403 or transport timeouts. | Fallback permission is limited to `ApprovalTimeout`; the explicit execute mode remains intentionally fail-open. |
| 400/401/403/404/409/422/429/500/503 and transport failures | Exact status retained; no SDK retry of approval POST; text/list/message error bodies remain visible. | Retry amplification of non-idempotent POST is absent in these paths. Server replay deduplication is untested. |
| Legacy `/wait` support | Both approved and rejected fallback decisions return correctly. | Compatibility works for terminal decisions; pacing defect remains BE-001. |
| Arguments | 75 deterministic nested JSON values round-trip; six nonfinite float cases fail before transport. | Serialization safety for generated plain JSON values, not arbitrary Python object semantics. |
| Supporting endpoints | 14 sync/async cases inspect tenant, default approver, consent contact, revocation and audit methods, paths and bodies. | Internal SDK contract parity only; no checked-in OpenAPI/schema was found to validate server compatibility. |
| Audit transport errors | Sync/async transport errors remain best effort and do not replace the function outcome. | Matches the explicit best-effort comment; server persistence is unverified. |

## Limits and handoff

No browser/UI backend exists in this package. Screenshots would not establish Python client behavior; terminal reports and reproducible tests are the evidence. Root QA owns aggregate before/after coverage, full-suite checks and the dependency audit. Backend-only tests are not a statement that every optional adapter/framework combination works.

Still untested: real server authorization and audit durability, actual idempotency deduplication, real HTTP/TLS latency, thread races during lazy client construction, cancellation teardown, indefinite pending load, and every malformed success-envelope shape. Coverage is reported in `COVERAGE.md`; expected-failure execution contributes to coverage but does not mean those behaviors are correct.
